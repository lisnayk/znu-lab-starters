# Паспорт середовища — стартер лабораторної 1

Послідовність: локальний запуск → Vagrant / VirtualBox → AWS EC2.
Після кожного відкрийте GET / у браузері, перевірте свої дані та зробіть
скриншот з адресним рядком для звіту. Повний хід роботи — у Moodle.

## Отримання коду

У Linux/macOS або WSL, у робочому каталозі без наявного lab1:

```bash
git clone --depth 1 https://github.com/lisnayk/znu-lab-starters.git
cp -R znu-lab-starters/conteinerization/labs/01-vagrant/starter lab1
cd lab1
```

## Дані студента

Скопіюйте .env.example у .env, заповніть чотири значення в лапках:
STUDENT_FULL_NAME — ПІБ, STUDENT_GROUP — номер групи, STUDENT_YEAR — курс навчання,
STUDENT_PROGRAMME — освітня програма. Кодування UTF-8.
Зміни файла діють після перезапуску сервера. Заповнений .env не публікується.

## 1. Локально в Linux/macOS або WSL

У каталозі стартера, з Python 3.10+ і venv:

```bash
bash run.sh
```

Відкрийте http://127.0.0.1:8000/ та зробіть перший скриншот.
Зупиніть сервер через Ctrl+C.

## 2. Vagrant / VirtualBox

На сумісному хості x86_64, у тому самому каталозі:

```bash
vagrant up
vagrant ssh
```

У гості:

```bash
cd ~/lab1
HOST=0.0.0.0 bash run.sh
```

Відкрийте на хості http://127.0.0.1:8080/ та зробіть другий скриншот.
Після виходу з гостя видаліть власну VM командою vagrant destroy.

## 3. AWS EC2

Відкрийте user-data.sh і заповніть чотири STUDENT_* значення на початку скрипта.
Вони мають збігатися з вашим .env. Збережіть файл у UTF-8 з LF.
Порожні значення зупиняють скрипт із повідомленням про поле, яке треба заповнити.

У Learner Lab створіть погоджений інстанс Ubuntu Server 22.04 або 24.04 LTS.
У Security Group дозвольте вхідні TCP 22 і TCP 8000 для всіх IPv4-адрес:
джерело 0.0.0.0/0 (Anywhere-IPv4).
У Advanced details → User data вставте весь заповнений скрипт, починаючи з #!.

Скрипт отримує код із цього репозиторію, встановлює залежності, створює .env
і запускає службу passport від окремого користувача.
Для запуску застосунку підключення SSH не потрібне. Підготовка займає кілька хвилин.

Відкрийте http://PUBLIC_IP:8000/, де PUBLIC_IP — публічна адреса інстанса.
Перевірте дані студента й зробіть третій скриншот. Після роботи видаліть власні ресурси EC2.
Якщо сторінка недоступна, перевірте журнал /var/log/cloud-init-output.log
та службу командою systemctl status passport через SSH.
На перезавантаженнях службу запускає systemd; user data типово виконується лише вперше.

У відкритий репозиторій передається лише незаповнений шаблон user-data.sh.
Персоналізовану копію скрипта, .env та приватні ключі не публікуйте.

check.py та expected.txt залишаються допоміжними засобами розробника;
для звіту потрібна тільки сторінка GET / у кожному середовищі.
